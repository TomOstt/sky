# Sky v0.1: first release spec

Status: approved by Tom on 2026-09-29. Owner: Product Manager. Date: 2026-09-29.

## Goal
Prove Sky's core bet: units, tensor shapes, and matrix properties can be checked together, before anything runs, in a language that reads like Python. v0.1 is a checker plus an interpreter. It is not fast yet, and that is deliberate.

## Who it's for
Physicists, engineers, and scientific-ML developers who have shipped a unit or shape bug and would rather have the compiler catch it. The first users are us and a handful of early testers. We have no user data yet, so we will validate that this pain is real in early interviews rather than assume it.

## Why pick Sky over Julia + Unitful + ModelingToolkit
Julia checks units and shapes when code is compiled for specific argument types or when it runs, and each concern lives in a separate package. Sky checks units, symbolic shapes, and matrix properties in one static pass over the whole program, with a single set of error messages, before any data exists. v0.1 will not compete with Julia on speed or ecosystem, so the pitch for this release is correctness only.

## In scope
- Syntax: indentation-based, Python-like functions, `if`/`elif`/`else`, `while`, and bindings. Every Unicode operator (`∂`, `⁻¹`, `ħ`) has an ASCII spelling. `±` is not part of v0.1: uncertainty is out of scope, so the lexer rejects the glyph, and the ASCII `+-` is just `+` followed by unary `-`.
- Identifiers must be in Unicode NFKC form (Normalization Form KC, Unicode 18.0.0). A non-NFKC identifier, such as `e` followed by U+0301 instead of `é`, `ﬁ`, fullwidth `ｘ`, mathematical `𝑥`, or MICRO SIGN `µ`, is an error. It is never silently normalized, and keywords match only their exact ASCII spelling.
- An identifier may have at most 30 combining marks in a row (the Unicode stream-safe limit, UAX #15: characters with a nonzero canonical combining class, counted in each character's full compatibility decomposition, so U+0344 counts as two). A 31st mark in a row is an error at that mark.
- Units: the seven SI base units (m, s, g, K, A, mol, cd), derived units (J, N, Pa, W, Hz, C, V, Ω, F, T, Wb, H, S, rad, L, t), SI prefixes (`km`, `ms`, `μm`, `GeV`), the non-SI units min, h, day, yr, ly, pc, AU, eV, and physical constants (`c`, `h`, `ħ`, ...) as predefined names. A unit may follow only a numeric literal (`10 km`). `5 meters + 20 kelvin` is a compile error.
- Shapes: `Matrix[M, N]` and `Tensor[...]` with symbolic dimension variables solved by equality. `Matrix[3,4] @ Matrix[4,8]` gives `Matrix[3,8]`, and a mismatch is a compile error.
- Matrix properties: tags such as Symmetric, PositiveDefinite, Diagonal, and Orthogonal, arranged in a subtyping lattice. `A⁻¹ @ b` with a positive-definite `A` is rewritten to a Cholesky solve, and `sky check --explain` shows the rewrite.
- Tools: `sky check`, `sky run` (tree-walking interpreter), and `sky repl`. Diagnostics include source spans, in the format defined in [`spec/diagnostics.md`](diagnostics.md).

### Operator precedence
The placement of `and`, `or`, and `not` is signed off by Eng Lead (2026-09-29). From loosest to tightest:

| level | operators | associativity |
|---|---|---|
| 0 | `a if c else b` | right (in the `else` arm); the condition `c` is an `or` expression |
| 1 | `or` | left |
| 2 | `and` | left |
| 3 | `not x` | prefix |
| 4 | `==` `!=` `<` `<=` `>` `>=` (also `≠` `≤` `≥`) | none: `a < b < c` is an error |
| 5 | `+` `-` | left |
| 6 | `*` `/` `@` | left |
| 7 | `-x` `+x` `∂x` `∇x` | prefix |
| 8 | `^` | right; its right operand may be a prefix expression (`2^-1`) |
| 9 | `A⁻¹`, `f(x)`, `M[i, j]`, `x.name` | postfix |

An array literal `[a, b]` is an atom (see "Array literals"), so it takes postfix forms: `[1, 2][0]`.

- `and`, `or`, and `not` are keywords. As with every keyword, they may still be used as an attribute name after `.` (`x.and`).
- `and` and `or` short-circuit: operands are evaluated left to right, and evaluation stops at the first operand that decides the result.
- `not a < b` is `not (a < b)`, `a < b and b < c` needs no parentheses, and `a and b or c` is `(a and b) or c`.
- `not` cannot be the operand of a tighter operator: `-not x`, `a < not b`, and `2^not x` are errors; write `-(not x)`.
- `&&`, `||`, and `!` are not operators. The lexer rejects `&`, `|`, and a `!` that isn't part of `!=`, and suggests `and`, `or`, and `not`.
- `-x^2` is `-(x^2)`.
- The conditional expression `a if c else b` (level 0) is looser than `or`, so `a or b if c else d` is `(a or b) if c else d`. Its `else` arm may be another conditional (`a if c else b if d else e` is `a if c else (b if d else e)`), but its condition may not: `a if b if c else d else e` needs parentheses. Anywhere a tighter operator wants an operand, a conditional needs parentheses: `(a if c else b) + 1`. Only the chosen arm is evaluated at run time. The checker types every part.

#### Booleans and conditions
Signed off by Eng Lead (2026-09-29).
- `true` and `false` are the Bool literals. They are keywords, so they can't be assigned to, but they may be attribute names after `.`. A unit may not follow them (`true m` is a parse error). `True` and `False` are ordinary names.
- The operands of `and`, `or`, and `not` must be `Bool` of shape `()` (a scalar), and the result is `Bool`. The same rule applies to the conditions of `if`, `while`, and conditional expressions.
- v0.1 has no truthiness. `0 m`, empty containers, and tensors are never implicitly true or false.
- A non-Bool or non-scalar operand is a checker error on that operand's span. For a scalar quantity, the help suggests a comparison such as `x != 0 m`. For a tensor, the help says that a condition must be a single `Bool` (shape `()`).
- At run time, `and` and `or` evaluate left to right and stop early. The checker still types every operand, so `true or (3 m + 2 s)` is a check error.

### Statements and assignment
The simple statement forms the parser accepts (a statement ends at a newline; blocks are in "Blocks and control flow" below):

```text
statement   := expr
             | target "=" expr
             | target compound_op expr
             | NAME ":" type [ "=" expr ]          (see "Type annotations")
target      := NAME
             | postfix "[" index_item ( "," index_item )* [ "," ] "]"
             | postfix "." ( NAME | KEYWORD )
compound_op := "+=" | "-=" | "*=" | "/=" | "^=" | "@="
index_item  := expr | [ expr ] ":" [ expr ]
```

- `x op= e` rebinds `x` to `x op e`, evaluating the target once; the result must have `x`'s declared type (unit, shape, tags) or it is a check error. `+=`, `-=`, `*=`, `/=`, `^=`, `@=` stand for `+`, `-`, `*`, `/`, `^`, `@`. There is no compound form for comparisons or `and`/`or`, and `**=` is an error (Sky writes powers as `^`, so use `^=`).
- Only a name can be annotated: `a.b: T = 1` and `A[0]: T = 1` are parse errors.
- Any other target is a parse error on the target: `f(x) = 1`, `(x) = 1`, `1 = x`, `a + b += 1`, and `true = 1`.
- Assignments don't chain: `a = b = c` and `x += y += z` are parse errors.
- Slices select a range along one axis: `A[0, :]` is row 0, `A[1:3]` is rows 1 and 2, and `A[:n, 2:]` leaves out a bound. A slice has no step: `A[1:2:3]` is a parse error. The same index items are allowed when reading and as a target.
- **The parser accepts index and attribute targets, but the v0.1 checker rejects writes through them.** Index writes (`A[i, j] = x`, `A[0, :] = v`) are check errors: that is the v0.1 checker's behaviour while array immutability is pending Tom's confirmation (see Open questions), not a settled language rule. Attribute writes (`a.b = x`, `x.true = 1`) are check errors too, until there is something whose attributes can be assigned.

### Blocks and control flow
Python-style blocks. The tokens (`Indent`, `Dedent`) come from the lexer's indentation rules; this section is the grammar on top of them and what the checker does with it.

```text
statement   := simple_stmt | if_stmt | while_stmt | def_stmt
simple_stmt := (the forms in "Statements and assignment")
             | "return" [ expr ]
             | "pass" | "break" | "continue"
if_stmt     := "if" expr ":" block { "elif" expr ":" block } [ "else" ":" block ]
while_stmt  := "while" expr ":" block
def_stmt    := "def" NAME "(" [ param { "," param } [ "," ] ] ")" [ "->" type ] ":" block
param       := NAME [ ":" type ]
block       := NEWLINE INDENT statement+ DEDENT
expr        := or_expr | or_expr "if" or_expr "else" expr        (level 0)
```

**Layout**
- A block is a line ending in `:`, then one or more lines indented further than the header, all at the same indentation; the first line back at the header's indentation (or the end of the file) ends it. Blocks nest. Blank lines and comment-only lines never end a block.
- **The body goes on its own indented line.** `if x: y = 1` is a parse error, with the help "put the body on its own indented line". Python allows it; Sky doesn't. With one canonical layout, spans, diffs and error recovery stay simple, a statement has one way to be written, and the `:` of a header can't be mistaken for the `:` of an annotation (`y: Matrix[3, 3] = ...`). The parser still reads the statement after the `:` as the body, so one mistake gives one error.
- **An empty block is an error**, with the help "use `pass`": `pass` is the statement that does nothing.
- `elif` and `else` must follow the block of an `if`/`elif` at the same indentation. `else if` is an error ("write `elif`"), and so is an `else` or `elif` with no `if` before it.
- Blocks count toward the nesting limit (256 levels) together with expressions: a block is one level, like a parenthesis. 257 nested `if`s are one clean error ("blocks are nested too deeply"), never a stack overflow, and the rest of that block is skipped.
- Not supported yet, each a precise error: `for` loops (there are no iterable values), `import` statements (there is no module loader wired into the language yet), and default parameter values (`def f(x=1)`). `equation`, `solve`, and `field` are reserved for a future version.
- A bad line does not desynchronize the blocks around it. After an error the parser resumes at the next line; a block header with an error still has its body read (and its errors reported), so the `Dedent` that ends the body is consumed by the right block.

**Conditions**
- The condition of `if`, `elif`, `while`, and of a conditional expression must be a `Bool` of shape `()` (see "Booleans and conditions": no truthiness). The diagnostic and its help are those of `and`/`or`/`not` operands, on the condition's span: "compare it instead, e.g. `x != 0 m`".
- Both arms of `a if c else b` must have the same dimension and shape, and the tags are joined (only the tags both arms guarantee survive). Otherwise it is an error on the `else` arm, with the `if` arm as a secondary label. Shapes are compared after substituting solved size variables; the check never unifies them (see below).

**Scoping**
- `if` and `while` bodies share the enclosing scope, as in Python. A `def` opens a new scope: its parameters and everything it assigns are local to it and disappear when the body ends.
- After an `if`, the states of the branches that can fall through are merged. A branch that ends in `return`, `break`, or `continue` (or in an `if`/`else` whose branches all do) does not fall through and takes no part. An `if` without `else` counts "no branch ran" as one more state.
  - A name bound in every state with the same type keeps that type. "Same" is the same dimension and shape; tags are joined.
  - A name bound in every state with different types is an error at the later binding: "`x` is a length here but a time in the other branch", with the earlier binding as a secondary label.
  - A name bound in only some states is *maybe-defined*: using it afterwards is an error, "`x` may be undefined here", with a secondary label at a binding and the help "assign it before the `if`". It is reported once per name.
- A `while` loop's body is checked once, from the state before the loop. What follows the loop merges every way out: the condition failing (before the first iteration, or after the body or a `continue`) and each `break`. A loop whose condition is the literal `true` can only be left by `break`. A name bound only inside the body is maybe-defined afterwards ("assign it before the loop"), and a name the body rebinds with a different dimension or shape than it had on entry is a conflict, as above.
- `break` and `continue` are errors outside a `while` of the same function (a `def` inside a loop does not inherit it). `return` is an error outside a `def`.

**Shape variables across branches and functions**
- Shape variables are solved by one constraint set for the whole module, and scopes never snapshot it. A constraint learned in a branch stays afterwards: a size variable names one size for the module, so `N = 3` learned in one branch is a fact about `N`, not about that path.
- Merges never unify. Two branches that leave a name with different shapes (after substituting solved variables) are a conflict, not a new constraint that neither branch wrote.
- A `def`'s size variables are its own: `N` in its annotations is not the module's `N`. After the body is checked, the variables its signature still leaves open are generic, and each call gets fresh copies, so `def apply(A: Matrix[N, N], b: Vector[N]) -> Vector[N]` can be called with size 3 and then size 4. A body that pins a variable (returning a `Vector[N]` where `Vector[3]` is declared) makes the function specific to that size.

**Functions**
- Parameter and return annotations use the same type grammar as bindings (see Type annotations): `def kinetic(m: kg, v: m/s) -> J`. An annotated parameter has the annotation's shape, tags and unit; an annotation with no unit (`Vector[3]`) is dimensionless, the convention of a binding annotation without a value. Leave a parameter unannotated to accept any unit. An unannotated parameter is unknown inside the body: nothing is checked against it and there is no error (Python-like). Duplicate parameter names are an error.
- The return type is the declared `-> T` when there is one: every `return` must have a value of that shape, and of that unit's dimension if `T` names one ("expected energy, found mass"); without a unit, the dimension is the one the returned values agree on. Without `-> T`, the type is inferred from the `return`s, which must all give the same type (dimension and shape, tags joined), or it is an error at the later one. Mixing `return value` with a bare `return` is an error. A function that returns a value on some path but can finish without returning on another is an error at its name ("can finish without returning a value"). A function with no `return value` at all returns nothing, and a call to it is unknown.
- A call checks arity ("`f` takes 2 arguments, found 3") and each argument against its annotated parameter (shape, then dimension), and has the function's return type. Calling something that is not a function is an error. A call whose return type is unknown (unannotated parameters flowing into it) is unknown, and an unknown value is never an error by itself.
- A function's own name is in scope in its body (recursion). A recursive call is checked for arity and annotated arguments, and its result is unknown.
- **Names in a body.** A body is checked where it is defined, against the names bound so far. (Python looks names up at call time; Sky checks them at definition time, so a function that calls a helper needs the helper defined above it. The error says so: "a function body sees only names defined above its `def`".) Assigning to a name inside a function binds a new local and never changes an outer name. `x += 1` on a name that belongs to an enclosing scope is an error (Python fails it at run time with `UnboundLocalError`), with the help to bind a new name.
- A user function named `inv` shadows the built-in `inv(x)`; without one, `inv(x)` is `x⁻¹` as before.
- The checker never runs user code: bodies are typed, not executed (Security non-negotiable 1).

### Unit literals
Signed off by Eng Lead (2026-09-29). A unit literal is a numeric literal followed by a unit. `~` below means the two tokens touch, with no whitespace between them.

```text
unit_literal := NUMBER unit                  (whitespace required between NUMBER and unit)
unit         := factor ( ~("*" | "/")~ factor )*
factor       := NAME ( ~"^"~ exponent )?
exponent     := [ "-"~ ] INT
              | "("~ [ "-"~ ] INT ~"/"~ INT ~")"
```

- A unit may follow only a numeric literal, separated from it by whitespace (`10km` is rejected by the lexer: "put a space before the unit"). Unit names are ordinary names; a name is a unit only when it directly follows a number.
- `*`, `/`, and `^` are part of the unit only when there is no whitespace on either side. A spaced `*` or `/` is an ordinary operator on the quantity. A `^` right after a unit with whitespace on either side (`10 m ^2`, `10 m^ 2`, `10 m ^ 2`) is a parse error: write `10 m^2` for a power of the unit or `(10 m)^2` for a power of the quantity. For `*` and `/` the spacing never changes the value, because `(10 km)/h` equals `10 km/h`. For `^` it does (10 m² vs 100 m²) and the dimension is the same, so the checker couldn't catch the difference.
- Compound units use `*`, never juxtaposition. `*` and `/` group left to right, and `^` binds tighter.
- An exponent is a signed integer or a parenthesized rational. The denominator must not be zero. The numerator must fit in a signed 64-bit integer and the denominator in an unsigned 64-bit integer.

#### Units and prefixes
- Base units: `m`, `s`, `g`, `K`, `A`, `mol`, `cd`. `kg` is kilo + gram and is the coherent SI unit (scale exactly 1).
- Derived: `J`, `N`, `Pa`, `W`, `Hz`, `C`, `V`, `Ω` (ASCII `ohm`), `F`, `T` (tesla), `Wb`, `H`, `S`, `rad`, `L` (litre, exactly 10⁻³ m³), `t` (tonne, exactly 10³ kg). Other units: `min` (60 s), `h` (hour, 3600 s), `day` (86 400 s), `yr` (Julian year, 365.25 d), `ly` (light-year, c × 1 yr), `pc` (IAU 2015), `AU` (IAU 2012), `eV` (exact, 2019 SI). Factors follow the SI Brochure, 9th edition, and IAU 2012/2015.
- Prefixes: `q r y z a f p n μ m c d da h k M G T P E Z Y R Q` (quecto to quetta). ASCII `u` is an alias for `μ` (the MICRO SIGN `µ` U+00B5 is not NFKC and is a lexer error; use `μ` U+03BC or `u`). Prefixes attach only to `m s g K A mol cd J N Pa W Hz C V Ω F T Wb H S rad L t yr ly pc eV`; `min`, `h`, `day` and `AU` take none (`kmin` is an error).
- Resolution: an exact unit name always wins over prefix + unit. Otherwise the name splits into one prefix and a prefixable unit. Consequences: `min` is the minute; `h` is the hour and `hPa` is hectopascal; `pc` is the parsec (`Mpc` mega-parsec); `Pa` is the pascal; `cd` is the candela (there is no unit `d`; write `day`); `ms`, `mm`, `nm` are milli/nano + unit; `T` is the tesla and also tera (`TT`, `mT`), and `t` is the tonne (`kt`); `da` is deca (`dam`) and `day` is the day; `Gyr` is giga-year and `Gy` is not a unit (the checker suggests `Gyr`). Full names such as `meters` or `micrometer` are not units; the checker suggests the symbol.
- Spellings are case-sensitive, and lookup is a pure function of the text: no unit is ever guessed.

#### Physical constants
Constants are values with a dimension, not units. They are predefined names in scope (the checker's prelude), so `E = 2 kg * c^2` is energy, and `10 c` is an error (a unit follows only a number; write `10 * c`). Values are CODATA 2018 in SI; the SI defining constants are exact.

| name | ASCII | meaning |
|------|-------|---------|
| `c` | | speed of light, exact |
| `h` | | Planck constant, exact |
| `ħ` (U+0127) | `hbar` | reduced Planck constant |
| `k_B` | | Boltzmann constant, exact |
| `N_A` | | Avogadro constant, exact |
| `q_e` | | elementary charge, exact |
| `G` | | gravitational constant |
| `ε0` | `eps0` | vacuum permittivity |
| `μ0` | `mu0` | vacuum permeability |
| `m_e`, `m_p`, `m_n`, `m_u` | | electron, proton, neutron, atomic mass |
| `σ_SB` | `sigma_SB` | Stefan-Boltzmann constant |
| `g_n` | | standard gravity, exact |

- The elementary charge is `q_e`, not `e`: `e` is the natural name for Euler's number and a common variable (eccentricity, error). `σ_SB` is not bare `σ`, which is a standard deviation or cross section in most programs. `ε0` and `μ0` are written without subscripts because a subscript zero is not NFKC (`ε₀` normalises to `ε0`, so it is a lexer error); `ℏ` U+210F is likewise not NFKC, so `ħ` is U+0127.
- A program may rebind a constant (`h = 0.1 s`), as with a Python builtin. The first rebinding of each name is a warning ("`h` shadows the Planck constant"), not an error. A size variable in an annotation may share a name with a constant that was not rebound.
- The hour `h` and the constant `h` never clash: units appear only after a number, constants only as names.
- `check_module_with` starts from the caller's environment as given; only `Env::with_prelude()` (used by `check_module` and so `sky check`) adds the constants.

Examples: `10 km`, `9.8 m/s^2`, `kg*m/s^2`, `3 s^-2`, `m^(1/2)`, `m^(-3/2)`.

Counter-examples:
- `10 km / 30 min` is `(10 km) / (30 min)`, and `10 m / t` is `(10 m) / t`: spaced `/` divides the quantity.
- `5 kg m` is a parse error; write `5 kg*m`.
- `x km` is a parse error, because a unit must follow a numeric literal; write `x * km`.
- `10 km` written as `10km` is a lexer error.
- `10 m/2`, `3 s^x`, and `1 m^(1/0)` are parse errors.
- `10 m ^2`, `10 m^ 2`, and `10 m ^ 2` are parse errors (ambiguous `^` after a unit); write `10 m^2` or `(10 m)^2`.

### Powers of quantities
- In `x^e` with a unit on `x`, the exponent `e` must be a constant number: an integer literal, a decimal literal, or a quotient of them, optionally negated or parenthesized (`(3 m)^2`, `(3 m)^-1`, `(3 m)^(1/2)`, `(3 m)^0.5`). Anything else is the error "the exponent must be a constant number".
- A decimal literal means exactly the fraction its text spells, never a float: `0.5` is 1/2, `1.5` is 3/2, `0.25` is 1/4, `2.0` is 2, `0.1` is 1/10. It is read from the source text and reduced. Exponent forms (`1e-1`) and literals whose numerator or denominator does not fit in a signed 64-bit integer are not constants.

### Unit values
- Types carry dimensions only. `km` and `m` are both the length dimension; there is no separate type per unit.
- Each unit has an `f64` factor to the coherent SI unit of its dimension (`km` is 1000, `min` is 60; a prefixed unit's factor is the prefix's power of ten times the unit's, exact when the unit's factor is itself a power of ten). The unit table in `sky-units` is the only place these factors live.
- A unit literal is converted to SI once, at the literal: `10 ms` is the value `0.01` with dimension time. After that no value remembers its unit, so `1 km + 1 m` is length plus length (the value `1001`), and there is no rule for mixing scales.
- A converted value is an ordinary `f64`, so arithmetic on it rounds like any float. `100 ms` is stored as `0.1`, and `3 * (100 ms)` is `0.30000000000000004`, so `3 * (100 ms) == 0.3 s` is false. Compare quantities with a tolerance, as with any float.
- v0.1 prints values in SI units: `10 ms` prints as `0.01 s`. Printing in a chosen unit such as `km` or `ms` is a later display feature.
- Offset units such as `°C` and `°F` (a unit that needs an added offset, not just a factor) are out of scope for v0.1. Temperature is written in `K`.

### Type annotations
`NAME: type` declares what a name is; `NAME: type = expr` also gives it a value. An annotation reads like English: "`A` is a positive-definite N by N matrix of kilograms". `~` means the two tokens touch, as in the unit-literal grammar.

```text
type  := tag* shape [ unit ]
       | tag* unit
       | "Scalar"
tag   := NAME                  (Symmetric, PositiveDefinite, Diagonal, Orthogonal)
shape := ( "Vector" | "Matrix" | "Tensor" ) "[" dim ( "," dim )* [ "," ] "]"
dim   := INT | NAME            (a NAME is a size variable)
unit  := factor ( ~("*" | "/")~ factor )*      (the unit-literal grammar)
```

```sky
t: s                                   # scalar time
v: Vector[3] m/s                       # vector of velocities
A: PositiveDefinite Matrix[N, N]       # tags before the shape
K: Symmetric Diagonal Matrix[3, 3] N/m
x: Scalar                              # dimensionless scalar
M: Tensor[B, T, D] kg
```

- **A lone name is always a unit.** `x: N` is newtons and `x: K` is kelvin, never a size variable. Size variables exist only inside `[...]`, so `A: Matrix[N, N] N` is an N by N matrix of newtons. A bare unit means a scalar of that unit; `Scalar` alone is a dimensionless scalar (it takes no unit: write `x: m`, not `x: Scalar m`).
- **The parser tells the parts apart by position.** After optional tags, a name followed by `[` is a shape, and `Vector`, `Matrix`, `Tensor` and `Scalar` are the only shape words. Any other name starts the unit, which must be followed by nothing or by a touching `*`, `/` or `^` (so `m/s^2`, `kg*m^2`). Leading capitalized names are tags when they run up to a shape word, so `PositiveDefinite Matrix[3, 3]` has one tag and `Symmetric Diagonal Matrix[3, 3]` two. One of the four property words followed by another name also starts the tags (`Symmetric m`, which the checker reports as a property without a shape). The checker validates tag names, and a misspelling gets `unknown matrix property` with a did-you-mean.
- **Declaration without a value is an input.** `A: PositiveDefinite Matrix[N, N] kg` binds `A` with those tags, shape and unit, taken on trust. This is how a program gets a positive-definite matrix without spelling its entries, and so how `A⁻¹ @ b` reaches the Cholesky rewrite when the entries are not literals. `sky run` has nothing to read such an input from yet, so running a declaration without a value is a runtime error (`` `A` is declared but has no value ``); a literal with a proven tag (below) is the way to run one.
- **With a value, the value must agree.** The shape must unify. If a unit is declared, the value's dimension must equal it (`expected mass, found length`). If tags are declared, the value's closed tag set must include them (`B is not known to be PositiveDefinite`): the checker only knows properties it can prove, from a declaration or an operation that preserves them. Without a declared unit the dimension comes from the value, and is dimensionless when there is no value. The value must be a number, never a Bool.
- Tags need a square matrix shape: `Symmetric Vector[3]` and `Diagonal Matrix[3, 4]` are errors.
- Parse errors, each with the correct spelling as help: a tag after the shape (`Matrix[3, 3] PositiveDefinite`; the checker reports this one, because only it knows the tag names), a value where a type belongs (`x: 5 m`), juxtaposed units (`x: m s`, write `m*s`), spaces around a unit's `*`, `/` or `^` (`x: m / s`), slices, arithmetic (`Matrix[N+1, N]`) and non-integer dimensions in `[...]`.
- A compound unit written with a space is an error with a help pointing at `*`, whatever the case of its first name: `x: N m` suggests `N*m`, and `x: Pa s` suggests `Pa*s`.

### Matrix tags
- PositiveDefinite and Diagonal each imply Symmetric, so a PositiveDefinite or Diagonal matrix can be used where a Symmetric one is expected.
- This holds only because every element of a v0.1 matrix has the same unit. Once matrices can mix element units, whether a matrix is symmetric will depend on its units as well as its values, and this rule will need revisiting.

### Array literals
```text
array := "[" expr ( "," expr )* [ "," ] "]"
```

- `[1 m, 2 m, 3 m]` is a `Vector[3]` of lengths. `[[1, 2], [3, 4]]` is a `Matrix[2, 2]`, written as rows: it is an array whose elements are all array literals, and the row length is the number of columns. Matrices may be spread over several lines, since newlines inside brackets are not statement ends.
- The parser only reads nested brackets; the checker decides the shape. A literal is a scalar list, or a list of scalar lists. Mixing scalars and rows (`[1, [2, 3]]`), a third level of nesting, and an element that is not a number (a Bool, a name bound to a vector) are errors on that element.
- **Every element must have the same dimension.** `[1 m, 2 s, 3 m]` is an error on `2 s` (the dimension held by most elements is the expected one, the first on a tie), and the other elements are not reported. In a matrix the rule covers every entry. Rows must have equal lengths; a row that differs from the rest (again by majority, first on a tie) is an error on that row.
- **Empty literals are rejected**, at parse time: `[]` is an error. An empty literal has no element to fix the dimension of its entries, so `[]` would have to be dimensionless and could then never be added to a vector of lengths, or it would need a type annotation from context, which Sky's inference does not have. Nothing is lost: an all-zero vector is `zeros(n)`, and a zero-length array has no use in v0.1 (`zeros(0)` is an error too).
- The type of a literal is exact: `Vector[3]` or `Matrix[2, 2]`, with the element dimension and **no tags**. A literal can be bound to a declared type that has the same shape and dimension (`v: Vector[2] m = [1 m, 2 m]`; the declared unit must match the entries, so `K: Matrix[2, 2] N/m = [[2, 1], [1, 2]]` is an error, as it is for a scalar).

#### Tags on literals
A declared tag is a promise the checker must be able to keep. For a literal it can be kept from the entries, but only when **every entry is a numeric literal**: a number or a number with a unit, optionally negated (`2`, `-1.5`, `3 N/m`, `-(2)`). Then the checker reads the values as the interpreter will (the same `f64`, after the unit's conversion to SI), and proves:

- **Symmetric**: the matrix is square and `aᵢⱼ == aⱼᵢ` for every pair, exactly.
- **Diagonal**: the matrix is square and every off-diagonal entry is exactly zero.
- **PositiveDefinite**: the matrix is Symmetric, at most 32 by 32, and a Cholesky factorization `A = L·Lᵀ` in `f64` finds every pivot larger than `1e-9` times the largest diagonal entry. This is pure arithmetic on constants the source spells out; it runs no user code, and the checker still never evaluates anything else. The margin is far above the rounding error of a factorization this small, so a proof is not a rounding artifact, and a positive-definite matrix that is that close to singular (condition number about 1e9 or worse) is simply not proven. Declare such a matrix as an input if you need it.
- **Orthogonal** is never proven for a literal: it needs exact equality of sums of products, which decimal entries such as `0.6` and `0.8` do not give in `f64`. (`identity(n)` is Orthogonal.)

If any entry is not a numeric literal (`[[a, 1], [1, a]]`, `[[2 * x, 1], [1, 2]]`) nothing is proven and the usual "not known to be" error stands, with a note that says why. If the entries are all constants and the property is false, the error names the failing entry (`entry [0, 1] is 2 but entry [1, 0] is 3`).

### Arrays: indexing, builtins and operations
- **Reading.** `v[i]`, `A[i, j]` and slices (`A[0, :]`, `v[1:3]`, `A[:n, 2:]`). An index is a dimensionless integer; a slice is `start:stop` with `stop` excluded and either bound optional. A scalar index removes its axis and a slice keeps it, so `A[0, :]` is a `Vector` and `A[0:1, :]` a `Matrix[1, N]`. Fewer indices than axes leave the trailing axes whole (`A[0]` is row 0). The element dimension is kept and the result has no tags. **Writes stay check errors: arrays are immutable in v0.1.**
- **Bounds.** A constant index or slice bound is checked against a known axis length at check time (`v[3]` on a `Vector[3]` is an error on the index). A variable one, or an axis with a symbolic length, is checked when the program runs. Indices are never negative, and a slice is never empty: arrays have at least one element on every axis, so `v[2:1]` is an error.
- **Slice length.** With constant bounds the length is known (`v[1:3]` is `Vector[2]`); otherwise the result has a fresh size variable that equals only itself.
- **Builtins.** `zeros(n)` is a `Vector[n]` and `zeros(m, n)` a `Matrix[m, n]`; `identity(n)` is a `Matrix[n, n]`; all are dimensionless (scale with `3 m * zeros(2)`). `len(x)` is the length of the first axis, as a dimensionless number. Sizes are part of the type, so they must be constant positive integers, and an array may have at most 2^24 elements. `identity(n)` has every matrix tag, `zeros(n, n)` is Diagonal. Like `print` and `inv`, a user binding with the same name shadows the builtin. The `I` in checker help text is written `identity(n)`.
- **Operations (run time).** `+` and `-` between arrays of one shape and dimension are elementwise; `*` and `/` scale by a number (`2 * v`, `v / 2 s`); `-v` negates. `@` multiplies matrix by matrix, matrix by vector, vector by matrix, and vector by vector (a dot product, so a number); dimensions multiply. `A⁻¹` and `inv(A)` invert a square matrix with the inverse dimension. There is no transpose syntax yet, and no elementwise `*` between arrays.
- **Inverse.** Gauss-Jordan elimination with partial pivoting. A matrix whose pivot is zero, or no larger than `n · ε · max|aᵢⱼ|`, is singular: a runtime error on the expression, never `inf`. The inverse of an exactly symmetric matrix is computed as one triangle and mirrored, so it is bitwise symmetric (the checker tags it Symmetric; see `tag_ops::needs_mirroring`).
- **Cholesky solve.** When the checker rewrites `A⁻¹ @ b` (a PositiveDefinite `A`; the site is in `Checked::cholesky_solves`), the interpreter factors `A = L·Lᵀ`, then solves `L·y = b` and `Lᵀ·x = y`; `A⁻¹` is never formed. `b` may be a vector or a matrix of right-hand sides. The rewrite is honoured by the span of the whole `A⁻¹ @ b` expression. Because an input's tags are taken on trust, the interpreter verifies the promise: an `A` that is not exactly symmetric, or has a pivot that is not positive, is a runtime error naming the fact.
- **Finite.** Every entry of every result must be finite; an overflow anywhere is a runtime error on the expression, like a scalar.
- **Printing.** An array prints as a valid Sky literal, entries in SI, each with its unit: `[1 m, 2 m]`, `[[1, 2], [3, 4]]`, `[0.1 m, 0.2 m]`. Numbers follow the scalar rules.

## Running programs
`sky run` and `sky repl` are a tree-walking interpreter over the checked AST. Vectors and matrices run: an array is its dimension, its shape (one or two axes) and its entries as `f64`, row-major. It is not fast, and that is deliberate (see Goal).

### `sky run <file>`
- The file is opened, size-capped and discovered exactly as `sky check` does, then lexed, parsed and checked.
- **Any error stops the run before anything executes**: the diagnostics go to stderr and the exit status is 1, so a `print` before a type error on a later line prints nothing. Warnings (such as a confusable identifier) are shown and the run continues.
- Program output (`print`) goes to stdout. Diagnostics, including runtime errors, go to stderr. A runtime error is an ordinary diagnostic on the failing expression, exit status 1. Output written before the failure stays.
- Top-level expression statements are evaluated and not printed, as in a Python script; only `print` writes.
- Blocks run as in Python: `if`/`elif`/`else`, `while` with `break` and `continue`, `a if c else b`. A `def` binds a function value; a call evaluates its arguments in the caller, then runs the body with the parameters as locals. Inside a function, a name is read from its locals and then from the module; assignments make locals.
- Recursion is limited to 1000 nested calls ("recursion is too deep"). Independently, the interpreter measures how much of its stack it has used and stops with "the program nests too deeply for the interpreter" before it could overflow, which a debug build reaches sooner. Neither is ever a crash.
- Exit status: 0 on success, 1 on a check or runtime error, 2 for a usage error or an unreadable file.
- `sky check` never executes code and is unchanged (non-negotiable 1).

### `sky repl`
- Reads stdin one input at a time. Each input is lexed, parsed and checked against the checker environment the earlier inputs built, then run against the runtime bindings they built.
- A top-level expression prints its value (like Python's REPL); an assignment prints nothing.
- An input with any error changes nothing. The checker environment is replaced only after a clean check, and the runtime bindings are restored if the run fails part way, so `a = 1` followed by `b = a / 0` on one line leaves neither bound.
- The prompt `sky> ` goes to stderr, and only when stdin is a terminal, so piped input gives clean stdout. End of input (Ctrl-D) exits 0. There is no line editing.
- **No session saving.** A session lives only in memory: v0.1 writes no session file and reads none back, so there is no serialized format to attack (non-negotiable 3). If saving is added it must use a data-only format.
- Multi-line input (blocks) is not supported yet: a `def`, `if` or `while` must be in a file run with `sky run`.

### Values and printing
- A value is a number with a dimension, an array of numbers of one dimension (a vector or a matrix, see "Arrays"), a Bool, or a string. A unit literal is converted to SI once, at the literal (see Unit values); a compound unit applies its factors one at a time, so `36 km/h` is exactly `10 m/s`. Numeric literals may contain `_` (`1_000`).
- `print(a, b, ...)` writes the values separated by single spaces and a newline; `print()` writes an empty line. A string prints as is. A user binding named `print` (or `inv`) shadows the builtin, in the checker and at run time.
- Values print in SI, as valid Sky source, so REPL output can be pasted back:
  - a dimensionless number prints bare: `0.5`;
  - a dimension that matches a unit with scale 1 in the unit table prints with it: `10 N`, `2 J`, `3 W`, `101325 Pa`, `50 Hz`;
  - any other dimension is composed from `kg`, `m`, `s`, `K` in that order, positive powers first, as `kg*m^2/s^2/K`, `m/s^2`, `m^-1`, `m^(1/2)`;
  - `10 ms` prints as `0.01 s`; a string echoes quoted and escaped (`"a\n"`).
  - `Hz` and `rad/s` share a dimension, so a value that is really an angular frequency prints as `Hz` (the known limitation in the unit table).
- Numbers print with the shortest digits that read back as the same `f64`: in plain decimal for magnitudes from 1e-4 up to (but not including) 1e16, and as `6.674e-11` outside that range. `0.1 + 0.2` prints `0.30000000000000004`, which the "Unit values" rules already accept.
- Booleans print as `true` and `false`.

### Arithmetic
- Numbers are IEEE `f64`, but **a Sky number is always finite**. Division by zero, an overflowing result (a finite operation whose result does not fit, such as `1e308 * 10`), a number literal too large for `f64`, and an operation with no real result (`(-8)^(1/3)`) are runtime errors on the failing expression. They never produce `inf` or `NaN`. Underflow to zero is not an error.
- Why: a scientist coming from Python expects `1/0` to stop the program (`ZeroDivisionError`), and a silent `inf` or `NaN` carried through a simulation gives a correctly-typed, correctly-united wrong answer. It also means no value is ever NaN, so `==` and the orderings are total and need no special cases.
- `^` uses repeated multiplication for an integer exponent of at most 64 in size (so `2^10` is exactly 1024) and `powf` otherwise. The result's dimension is the base's dimension raised to the constant rational exponent read from the source, as the checker computes it; a dimensionless base may take any dimensionless exponent.
- `x⁻¹` and `inv(x)` are `1/x`, with the inverse dimension.
- `and` and `or` evaluate left to right and stop at the first operand that decides the result; the operands not reached are never evaluated (`false and (1/0 > 0)` is `false`). There is no truthiness: an operand that is not a Bool is a runtime error, as it is a check error.
- Comparisons compare the SI values, and `==` between floats is exact (`3 * (100 ms) == 0.3 s` is false).
- The interpreter re-checks operand kinds and dimensions dynamically and reports a runtime error, never a panic, because the checker leaves some expressions (strings, calls it has no rule for) with an unknown type. Index and attribute writes are check errors, so a checked program never reaches them.
- Not supported yet, and a runtime error if reached: a declaration without a value (an input), attribute reads, and the `∂` and `∇` operators. There is no transpose syntax.

## Out of scope for v0.1
Native codegen, MLIR, and GPU targets; symbolic simplification and autodiff; PDE and equation solving; automatic solver selection beyond the one rewrite above; automatic precision; uncertainty (`±`) propagation; offset units such as `°C`; printing values in non-SI units; dimension arithmetic such as `N+1`; packages and plugins; notebooks.

Not yet available, though in scope for a later step: `for` loops (there are no iterable values yet) and `import` statements (the project-root resolver exists, but nothing in the language calls it yet). The parser reports both as "not supported yet", precisely, and `equation`, `solve`, and `field` as reserved.

## Non-negotiables (from Security Officer)
1. `sky check` never executes user code: no build scripts, macros, or impure compile-time evaluation.
2. Imports resolve only from the project root and the standard library, never from the working directory or environment variables.
3. Saved REPL sessions and caches use a data-only format, with no pickle-style serialization.
4. The lexer rejects bidi control characters and flags confusable identifiers.

## Imports and the project root
These rules implement non-negotiable 2. "Must" is normative.
- The project root is the nearest directory containing `sky.toml`, walking up from the checked file's directory. The walk stops after a directory containing `.git`, the user's home directory (from the passwd database), or the filesystem root. A `sky.toml` that is a symbolic link or not a regular file, or that (or its directory) is owned by another user, is refused. So is a `sky.toml` that is world-writable (the sticky bit does not matter for a file), or a root directory that is world-writable without the sticky bit: the same mode rules as the per-directory rule below, applied to the root at discovery so a root is never accepted and then refused at the first import. With no `sky.toml`, only standard-library imports resolve.
- **No `sky.toml` field may add import search paths or point resolution outside the project root.** Project imports resolve only to files under the root.
- `import a.b.c` names `<root>/a/b/c.sky`. Module names are ASCII identifiers, so a segment is never `..`, empty, or a path separator. A project module may not shadow a standard-library name.
- Resolution walks from the root using directory handles, never by rechecking a path. It opens the root, then each directory relative to the one before, then the module file relative to the last directory. It follows no symbolic links: a link anywhere below the root, even one that stays inside it, is refused.
- **Per-directory rule:** the root and every directory down to the module file's parent must be owned by the effective user and must not be world-writable unless the sticky bit is set. The module file must be a regular file owned by the effective user and must not be world-writable; the sticky bit does not matter for files. Group-writable directories and module files are allowed.
- The module is read from the handle opened during resolution and is never reopened by name. The file `sky check` is given is read the same way: from a single handle, which must be a regular file (never a FIFO or device), of at most 16 MiB (16,777,216 bytes), in UTF-8. The size limit applies both to the file's size when it is opened and to the number of bytes actually read.
- Off Unix, where handle-relative opens aren't available, any project with a `sky.toml` is refused.

## Done means
- Golden tests in `tests/ui/` cover every example in this spec, both passing and failing cases.
- A physicist unfamiliar with Sky can write and check a small kinematics script in the REPL in under 15 minutes (target to test with a few people, not a measured result).
- The parser fuzz target and `cargo-deny` run in CI.
