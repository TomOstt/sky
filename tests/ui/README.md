Golden tests: each `.sky` file here has an expected-output file with its diagnostics. Passing and failing examples both live here.

- `foo.sky` is checked with `sky check tests/ui/.../foo.sky` (run from the workspace root), and its stderr must equal `foo.stderr` byte for byte. An empty `.stderr` means the file must check cleanly. Diagnostics use the format in `crates/sky-diag` (see `spec/diagnostics.md`); several diagnostics are separated by one blank line.
- The exit status must be 1 if `foo.stderr` contains an `error:` header and 0 otherwise (warnings alone do not fail a check).
- If `foo.explain` exists next to `foo.sky`, the harness also runs `sky check --explain tests/ui/.../foo.sky` and its stderr must equal `foo.explain` byte for byte (it holds the diagnostics followed by the rewrite notes). This pins the Cholesky rewrite end to end; an empty `foo.explain` pins "no rewrite". `foo.types` is not run here: it belongs to the sky-types runner (see `types/` below) and the harness ignores it.
- The harness is `crates/sky-cli/tests/ui.rs`; it walks every subdirectory. Regenerate expectations with `SKY_BLESS=1 cargo test -p sky-cli --test ui` and review the diff.
- Files here are stored byte for byte (`.gitattributes`: `-text`), because some tests depend on CRLF, tabs, or bidi/control characters.
- `check/`: `sky check` end to end: parser diagnostics, the parser depth limit (256 levels ok, 257 an error), a lexer error that stops the check before parsing, `true`/`false` literals (and a unit after a Bool, which is an error), and a unit mismatch reported by the type checker (`err_unit_mismatch.sky`), a derivative (`ok_derivative`, and `err_derivative_unit`: the derivative of a position is a velocity, not a length), and blocks and control flow (`ok_kinetic`, `ok_control_flow`, `err_control_flow`, and the block depth limit: `ok_block_depth_256` / `err_block_depth_257`, one tab per level). `crates/sky-cli/tests/check_parse.rs` checks their stdout (`ok`) and exit codes. `ok_condition_warning` and `ok_cancellation_warning` pin the numerical warnings end to end (a warning alone exits 0); the full set is in `crates/sky-types/tests/ui/` (`ok_condition_*`, `ok_cancellation_*`).
- `types/`: type annotations and the checker semantics that need declared names: shapes, matrix property tags, and element units (`A: PositiveDefinite Matrix[N, N]`, `v: Vector[3] m/s`). `ok_cholesky_declared.sky`, `ok_cholesky_rewrite.sky` and `ok_cholesky_literal.sky` (a PositiveDefinite matrix literal, proven from its entries) have `.explain` files that pin the `A⁻¹ @ b` rewrite. `ok_array_*`, `ok_literal_tag_proofs`, `err_array_*` and `err_literal_tag_*` cover array literals, indexing, the `zeros`/`identity`/`len` builtins, and tags proven (or not) from literal entries. The `.types` files (every binding's type after the last statement, `name: type` in name order) are checked by `crates/sky-types/tests/ui_check.rs`, which reads this directory for them.
- `lexer/`: tokens, indentation, and the lexer's security checks (`ok_*` clean, `warn_*` warnings only, `err_*` errors). `ok_*` means the lexer accepts the file; later phases add their diagnostics, so some `ok_*` goldens carry parser or type-checker errors (undefined names, units not in the table). Since `sky check` runs the parser, the `ok_*` files that use `for`, `import`, or the reserved words (`equation`, `solve`, `field`) still carry the parser's "not supported yet" / "reserved" errors; blocks (`def`, `if`, `while`) parse now and add nothing.

Golden tests for `--emit-ir` and the passes' `--explain` notes are in `tests/ir/` (see `crates/sky-cli/tests/emit_ir.rs`): `NAME.sir` is the stdout of `sky check --emit-ir NAME.sky`, `NAME.lower.sir` of `--emit-ir=lower`, `NAME.explain` the stderr of `--explain`, and `NAME.stderr` the note for a program that has no IR yet. Bless with `SKY_BLESS=1 cargo test -p sky-cli --test emit_ir`.
- `lexer/`: tokens, indentation, and the lexer's security checks (`ok_*` clean, `warn_*` warnings only, `err_*` errors). `ok_*` means the lexer accepts the file; later phases add their diagnostics, so some `ok_*` goldens carry parser or type-checker errors (undefined names, units not in the table). Since `sky check` runs the parser, the `ok_*` files that use `import` or the reserved words (`equation`, `solve`, `field`) still carry the parser's "not supported yet" / "reserved" errors; blocks (`def`, `if`, `while`, `for`) parse now and add nothing.
